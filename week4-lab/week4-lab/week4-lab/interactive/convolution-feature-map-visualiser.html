The kernel is nine numbers. It does not change as it walks. That single fact is the stationarity assumption: a feature worth detecting in one corner is worth detecting everywhere, so the same detector is reused at every position.
Worth doing. Set the kernel to the vertical edge detector and note where the feature map lights up. Now switch to horizontal and watch a completely different set of positions respond, from the same image and the same nine-number machinery. Then set padding to 0 and watch the output shrink, and set stride to 2 and watch it halve. The size arithmetic is out = (n + 2p − k) / s + 1 and the readout above checks it for you.

One image, six filters, six feature maps

A convolution layer is not one filter. It is a bank of them, each asking a different question of every position, and each producing its own channel.

Six filters of nine weights each is 54 weights plus 6 biases. A dense layer connecting 32 x 32 pixels to 128 units needs 131,200. Both look at the whole image. Only one of them assumed anything about it.
Worth doing. Turn ReLU off and on. With it off, an edge and its opposite produce mirror-image responses that partly cancel later; with it on, each filter reports only the polarity it was built for, which is why the next layer can treat "this edge, this way round" as a feature. Then switch on max pooling and notice the maps get smaller and blockier: that is position information being deliberately discarded in exchange for a little tolerance to movement.

The arithmetic

The recurrence, layer by layer. No global rule is ever written down.

The point. A single 3 x 3 convolution sees nine pixels and nothing else. Stack a few, with the occasional pool, and one unit near the top depends on the whole image. Global understanding was built out of purely local operations, and nobody ever wrote a rule about the picture as a whole. This is compositionality, the third assumption, and it is why the layers of a trained CNN go edges, then textures, then parts, then objects.

Choose shift and the edge response moves but survives: a convolution is equivariant to translation, so shifting the input shifts the output and changes nothing else. Choose shuffle and the edge response collapses, even though every single pixel value is still there and the histogram is identical. The convolution never cared about the values. It cared about which values were next to which.
This is the experiment inductive_bias.py runs on a trained network. There, the CNN goes from 0.99 accuracy to chance under exactly this permutation, while the dense network does not move at all. The CNN's advantage was never general capability. It was an assumption about neighbours, and this tab is that assumption being removed.
